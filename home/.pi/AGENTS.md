# pi agent workspace

npm workspace for the global pi extensions. TypeScript, ESM only. `dot link` symlinks these files into `~/.pi`.

## Structure

```
home/.pi/
├── package.json          # Workspace root: workspaces = ["agent/extensions/*"]
├── tsconfig.json         # Strict, bundler mode, ESNext, noEmit
└── agent/
    ├── AGENTS.md         # Global working rules for every pi session
    ├── cloak.json        # Secret masking for files the agent reads
    ├── keybindings.json  # pi TUI keys (Shift+Enter inserts a new line)
    └── extensions/
        ├── herdr-codemode/            # Package: Herdr SDK as codemode tools (tools.herdr_*)
        ├── pi-skill-toggle/           # Package: /toggle-skills, automatic or manual-only
        ├── pi-worktrees/              # Package: /worktrees manager; uses the worktrees skill script
        ├── save-md/                   # Package: /save-md, saves the last reply as Markdown
        ├── continue-after-compaction.ts  # Standalone: resumes work after compaction
        ├── git-interceptor.ts         # Standalone: no git editor hangs, blocks --no-verify
        ├── herdr-agent-state.ts       # Standalone: reports agent state to Herdr
        ├── pi-cloak/                  # Standalone: applies cloak.json
        ├── whimsical.ts               # Standalone: playful working messages
        └── tests/                     # Tests for standalone extensions
```

Skills live in `home/.agents/skills/` and link to `~/.agents/skills/`. Do not copy them into `agent/skills/`.

## Where to look

| Task | Location |
|------|----------|
| Create a package extension | `agent/extensions/<name>/` with its own `package.json` (`"pi": { "extensions": [...] }`) |
| Create a standalone extension | `agent/extensions/<name>.ts` |
| Secret masking | `agent/cloak.json` |
| Pi package from git or npm | `packages/pi-packages.txt` at the repo root, installed with `pi install` |
| Type-check and test | `npm run check` from `home/.pi` |

## Dependencies

Install from `~/.dotfiles/home/.pi`, not from `~/.pi`:

```sh
cd ~/.dotfiles/home/.pi && npm install
```

The links resolve to files in the repo, so Node looks for `node_modules` next to the real files. `node_modules/` is gitignored. After changing extension code, run `/reload` in pi.

## Conventions

- ESM only: `"type": "module"` everywhere.
- Shared dependencies go at the workspace root; extension-specific ones go in that extension's `package.json`.
- `herdr-codemode/vendor/herdr-sdk` is generated by `scripts/vendor-herdr-sdk.sh`. Do not edit it by hand.

## Not tracked

`settings.json`, `models.json`, `auth*.json`, sessions and caches stay on each machine. Providers and enabled models differ per computer.
